# 요구사항: VoiceParking 프로토타입

출처 표기: `intent-statement.md`(의도 정리), `Q<n>`(이 단계 질문지 답변), `desc`(최초 요청).

## Intent Analysis

- 목표는 음성 텍스트 한 줄로 최적 주차권을 추천받고, 결제와 예약까지 한 흐름으로 끝내는 프로토타입이다. (desc, intent-statement.md)
- 성공의 기준은 추천이 "왜 최적인지" 화면에서 설명되고, 결제 후 예약 완료가 바로 보이는 것이다. (intent-statement.md Success Metrics)
- 주 사용자는 음성으로 빠르게 주차장을 찾고 싶은 운전자다. (intent-statement.md Target Customer)

| ID | 요구사항 | 합격 기준 | 출처 |
|----|----------|-----------|------|
| FR1 | 음성 텍스트 입력 처리 | | desc |
| FR1.1 | 시스템은 "강남역 근처 2시간 주차권 찾아줘"와 같은 텍스트를 입력으로 받는다 | 해당 문장을 보내면 추천 단계로 넘어간다 | desc |
| FR1.2 | 시스템은 텍스트에서 목적지와 이용 시간을 뽑아낸다 | 위 문장에서 목적지 "강남역", 이용 시간 "2시간"이 뽑힌다 | desc |
| FR2 | 주차권 추천 | | desc, Q1, Q3, Q6 |
| FR2.1 | 시스템은 후보마다 종합 점수를 계산한다: 가격 40%, 거리 40%, 이용 시간 적합도 20% | 같은 입력과 같은 샘플 데이터에서 항상 같은 점수와 순위가 나온다 | Q1, Q6 |
| FR2.2 | 시스템은 최적 1개와 비교 후보 2개를 함께 보여 준다 | 추천 화면에 후보가 정확히 3개이고 그중 1개가 최적으로 표시된다 | Q3 |
| FR2.3 | 시스템은 최적 후보가 왜 최적인지 가격·거리·이용 시간 적합도 기준으로 설명한다 | 최적 후보 옆에 세 기준에 따른 설명이 표시된다 | intent-statement.md, Q3 |
| FR3 | 결제 | | desc, Q2, Q4 |
| FR3.1 | 사용자가 추천된 주차권을 골라 모의 결제를 시작할 수 있다 | 결제 시작 후 결제 대기 상태가 된다 | desc |
| FR3.2 | 모의 결제 승인은 비동기 웹훅으로 시스템에 전달된다 | 승인 웹훅을 받으면 해당 결제가 승인 상태로 바뀐다 | Q2 |
| FR3.3 | 결제가 실패하거나 취소되면 시스템은 사유를 안내하고 같은 추천 화면에서 다시 결제할 수 있게 한다 | 실패 후 사유 문구가 보이고 같은 후보로 재결제가 가능하다 | Q4 |
| FR3.4 | 승인이 180초 안에 오지 않으면 시스템은 예약을 자동으로 취소한다 | 승인 없이 180초가 지나면 예약이 취소 상태가 된다 | Q2 |
| FR4 | 예약 | | desc, Q5 |
| FR4.1 | 승인 웹훅을 받으면 시스템은 예약을 확정한다 | 승인 후 예약이 확정 상태로 조회된다 | desc |
| FR4.2 | 예약이 확정되면 사용자 화면에 예약 완료를 보여 준다 | 화면에 예약 완료와 예약한 주차권 정보가 표시된다 | desc |

## Constraints

- 프런트엔드는 Vue 3, 백엔드는 Java Spring Boot로 만든다. (desc)
- 백엔드 모듈이 여럿이면 마이크로서비스로 나눈다. 나누는 방식은 이후 설계 단계에서 정한다. (desc)
- 이 프로토타입은 `poc` 범위로 진행한다. (intent-statement.md Initial Scope Signal)

## Assumptions

- 음성은 이미 텍스트로 변환되어 들어온다. 진짜 음성 인식은 범위 밖이다. (intent-statement.md Initial Scope Signal)
- 주차권 데이터는 샘플 데이터이고 결제는 모의 결제다. (intent-statement.md Initial Scope Signal)
- 이용 시간 적합도와 거리를 점수로 바꾸는 구체적 공식(0~100 환산 방식)은 정해지지 않았다. 설계 단계에서 정하고 승인받는다. (Q6에서 비중만 확정됨)

## Out of Scope

- 실제 결제대행사(PG) 연동 (intent-statement.md Initial Scope Signal)
- 실제 주차장 데이터 연동 (intent-statement.md Initial Scope Signal)
- 진짜 음성 인식 (intent-statement.md Initial Scope Signal)
- 회원가입·로그인 등 계정 관리 (intent-statement.md Initial Scope Signal)

## Open Questions

- "근처"의 범위(목적지에서 몇 미터 이내를 후보로 볼지)는 정해지지 않았다. 이후 설계 단계에서 확인한다.
- 후보가 3개보다 적을 때 화면에 어떻게 보여 줄지는 정해지지 않았다.
- 시연 성공 횟수 기준은 정해지지 않았다.
