# u5-local-run 보안 요구사항

## Sources

- [scope] Workflow-selected scope: classic
- [memory:M1] requirements.md의 NFR6, NFR8, unit-of-work.md(U5), stories.md의 US5.1, contract-summary.md(포트와 웹훅 서명), phases/construction.md(비밀 값 하드코딩 금지, 입력 검증), u1~u4의 code-summary.md(환경 변수, 루프백 기본값, 프록시 의무)

이 유닛은 서비스가 아니라 실행 스크립트(packaging 유닛)라 기능 설계 단계의 산출물(functional-spec.md, rules.md)이 없다. 동작은 stories.md의 US5.1과 unit-of-work.md가 정한다. 이 유닛은 저장소 루트의 로컬 실행 스크립트다. 네트워크 서비스가 아니라 다른 네 유닛을 같은 머신에서 띄우고 비밀 값과 주소를 한곳에서 정해 넘긴다.

## 서비스별 주입 변수 (NFR8.1, NFR6.2, NFR6.3의 기준표)

스크립트가 서비스마다 넘기는 환경 변수는 아래뿐이다. 서비스 주소는 사용자가 바꾼 포트에서 스크립트가 계산해 넘긴다(포트만 바꿔도 서로 가리키는 주소가 함께 바뀐다).

| 서비스 | 넘기는 변수 | 값 |
|---|---|---|
| u1-search-service | `SERVER_PORT`, `SERVER_ADDRESS` | `U1_PORT`(기본 8081), `127.0.0.1` |
| u2-reservation-service | `SERVER_PORT`, `SERVER_ADDRESS`, `SEARCH_SERVICE_URL` | `U2_PORT`(기본 8082), `127.0.0.1`, `http://127.0.0.1:<U1_PORT>` |
| u3-payment-service | `SERVER_PORT`, `SERVER_ADDRESS`, `RESERVATION_SERVICE_URL`, `WEBHOOK_URL`, `PAYMENT_WEBHOOK_SECRET` | `U3_PORT`(기본 8083), `127.0.0.1`, `http://127.0.0.1:<U2_PORT>`, `http://127.0.0.1:<U3_PORT>/api/payments/webhook`, 비밀 값 |
| u4-web-ui | `U1_URL`, `U2_URL`, `U3_URL`, `UI_HOST` | `http://127.0.0.1:<U1_PORT>`, `...<U2_PORT>`, `...<U3_PORT>`, `127.0.0.1` |

화면의 포트 5173은 u4가 `strictPort`로 고정했으므로 바꿀 수 없다(NFR8.1에서 제외). 위 표에 없는 변수는 서비스에 넘기지 않는다.

| ID | 요구사항 | 측정 방법 | 출처 |
|---|---|---|---|
| NFR6.1 | 웹훅 비밀 값(`PAYMENT_WEBHOOK_SECRET`)은 스크립트와 설정 파일에 두지 않는다. 사용자가 환경 변수로 주면 그 값을 쓰고, 주지 않으면 실행마다 무작위 값을 만든다. 무작위 값은 32바이트 이상(16진수 64자 이상)이며 `openssl rand -hex 32`로 만들고 `openssl`이 없으면 `od -An -N32 -tx1 /dev/urandom`으로 만든다. | 스크립트·설정에서 비밀 값 패턴 검색 결과 0건, 환경 변수 없이 실행해 서비스가 기동하고 생성한 값의 길이가 64자 이상임을 시험(값 자체는 출력하지 않고 길이만 확인) | NFR6, BR3.2(u3) |
| NFR6.2 | 비밀 값은 u3 프로세스의 환경에만 넘긴다. u1, u2, u4를 띄울 때는 `PAYMENT_WEBHOOK_SECRET`을 환경에서 제거한다(`env -u PAYMENT_WEBHOOK_SECRET`). 사용자가 셸에 이미 내보낸 값이 있어도 다른 서비스가 상속하지 않는다. 비밀 값을 화면 출력, 로그 파일, 프로세스 인자(명령줄)에 쓰지 않으며 생성한 값을 파일에 저장하지 않는다. (같은 사용자의 프로세스는 환경을 볼 수 있다는 한계는 받아들인다.) | 시험용 가짜 서비스가 자기 환경을 파일로 남기게 해 u1·u2·u4 가짜에는 변수가 없고 u3 가짜에만 있음을 확인, 출력·로그·가짜 서비스의 인자에 값이 없음을 확인 | NFR6 |
| NFR6.3 | 모든 서비스는 루프백에서만 연다. 스크립트는 u1, u2, u3 모두에 `SERVER_ADDRESS=127.0.0.1`을, u4에 `UI_HOST=127.0.0.1`을 명시해 넘긴다. 사용자가 환경에 비루프백 `SERVER_ADDRESS` 또는 `UI_HOST`를 설정해 두었으면 덮어쓰지 않고 실행을 거부한다. `UI_ALLOW_NON_LOOPBACK`가 설정되어 있으면 값과 관계없이 거부한다(스크립트는 비루프백 허용 우회를 쓰지 않는다). | 비루프백 `SERVER_ADDRESS`, 비루프백 `UI_HOST`, `UI_ALLOW_NON_LOOPBACK=1`로 실행했을 때 거부하는 시험, 정상 실행에서 가짜 서비스가 받은 `SERVER_ADDRESS`가 모두 127.0.0.1임을 확인 | NFR6, u2·u3·u4의 루프백 의무 |
| NFR6.4 | 사용자가 준 설정값(포트, 비밀 값)은 사용하기 전에 검증한다. 포트는 1024~65535의 정수이고 세 서비스 포트는 서로 달라야 하며 어긋나면 어느 값이 틀렸는지 알리고 실행하지 않는다. 비밀 값은 공백·제어 문자·따옴표를 포함하지 않아야 한다. 설정값을 `eval`이나 따옴표 없는 확장으로 쓰지 않는다. | 잘못된 값별 시험(문자, 범위 밖, 같은 포트 둘, 셸 메타문자·공백이 든 비밀 값) | NFR6, 입력 검증 규칙 |
| NFR6.5 | 로그 파일은 저장소 안 `.local-run/logs/`에 쓰며 `umask 077`을 먼저 적용해 처음부터 소유자만 읽고 쓸 수 있다(0600). 로그는 실행마다 덮어써서(이어쓰지 않음) 무한히 커지지 않는다. `.local-run/`은 자체 `.gitignore`(내용 `*`)로 버전 관리에서 제외한다. 루트 `.gitignore`는 바꾸지 않는다. | 생성된 로그 파일의 권한(0600)과 두 번 실행해도 크기가 누적되지 않음, 자체 `.gitignore` 확인 | NFR6 |
| NFR6.6 | 화면 프록시가 결제 서비스의 웹훅 경로를 브라우저에 열지 않는다는 u3·u4의 의무는 이 스크립트가 바꾸지 못하게 한다. 스크립트는 프록시 대상 주소(`U1_URL` 등)만 넘기고 프록시 규칙을 건드리지 않으며, 연동 스모크(NFR8.7)가 브라우저 경로로 웹훅이 닿지 않음을 함께 확인한다. | 스모크에서 `POST /api/payments/webhook`(프록시 경유)이 결제 서비스에 닿지 않음 | NFR6, u3·u4 의무 |

## 위협 고려

| 위협 | 대응 |
|---|---|
| 비밀 값이 로그나 화면에 새어 나감 | NFR6.2: 출력·로그·명령줄에 쓰지 않음, 다른 서비스에 넘기지 않고 상속도 끊음 |
| 다른 기기가 서비스에 접속 | NFR6.3: 루프백 고정(u1~u4 모두), 비루프백 환경은 거부 |
| 잘못된 설정값이 셸 명령으로 실행됨 | NFR6.4: 형식 검증, `eval` 금지, 모든 확장에 따옴표 |
| 같은 머신의 다른 프로세스가 포트를 선점 | 기동 전 포트 점검으로 거부하고 어느 포트인지 알림(NFR8.3) |
| 로그 파일 열람 | NFR6.5: `umask 077`로 소유자만, 덮어쓰기 |

## Assumptions & Open Questions

- [assumption] 같은 사용자 계정의 다른 프로세스는 환경 변수를 볼 수 있다(`ps eww` 등). 개인 개발 머신이라 받아들인다.
- [assumption] 실행마다 만든 무작위 비밀 값은 u3와 모의 PG(같은 프로세스)만 알면 충분하다. 사용자가 외부 도구로 웹훅을 직접 호출하려면 `PAYMENT_WEBHOOK_SECRET`을 환경에 줘야 한다.
- 열린 질문: 없음.
