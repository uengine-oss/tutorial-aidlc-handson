| ID | 요구사항 | 측정 방법 | 출처 |
|---|---|---|---|
| NFR6.1 | 서버가 준 문자열(주차장 이름, 추천 이유, 안내 문구, 오류 메시지)은 모두 텍스트로만 렌더링한다. `v-html`과 `innerHTML`을 쓰지 않는다. | 소스 검색 결과 0건, `<script>`·`<img onerror>` 같은 문자열을 서버 응답에 넣은 시험에서 DOM에 요소로 만들어지지 않고 글자로만 보임 | NFR6, 보안 규칙 |
| NFR6.2 | 화면 소스와 설정에는 비밀 값(키, 비밀번호, 토큰)이 없다. 웹훅 비밀 값은 화면이 알지 못한다. | 소스·설정에서 비밀 값 패턴 검색 결과 0건 | NFR6 |
| NFR6.3 | 개발 서버 프록시는 `POST /api/payments`(정확 일치)만 결제 서비스로 보낸다. `/api/payments/webhook`, 끝 슬래시가 붙은 경로, `GET /api/payments`, 쿼리 문자열이 붙은 경로는 결제 서비스로 가지 않는다. `/internal/**`는 어느 서비스로도 연결하지 않는다. | 프록시 설정 모듈의 `bypass`·패턴 단위 시험과 실제 Vite 서버 통합 시험으로 위 경로가 서비스에 닿지 않음(404)을 확인 | NFR6, 결제 서비스(u3)의 필수 의무 |
| NFR6.4 | 세션 ID는 식별용 익명 UUID이며 비밀이 아니다. 헤더를 쓸 수 없는 구독(EventSource)에서만 URL 쿼리 `sessionId`로 보낸다. 이 값을 화면 어디에도 노출하지 않고 콘솔에도 기록하지 않는다. | 구독 외 요청에서 쿼리에 세션 ID가 없음, 로그 출력 시험 | NFR6, 계약 C3 |
| NFR6.5 | 입력은 시스템 경계에서 검증한다. 입력 텍스트는 앞뒤 공백 제거 후 1~200자, 시연 설정의 지연 초는 1~600의 정수로 맞춘다. 서버 응답은 필드 존재와 형식을 확인한 뒤 쓴다(알 수 없는 상태 값은 무시하고 화면 상태를 바꾸지 않는다). | 잘못된 입력·응답별 단위 시험 | NFR6 |
| NFR6.6 | 개발 서버는 루프백 주소에서만 연다(`server.host` 기본 `127.0.0.1`, 환경 변수로 바꿀 수 있다). | 프록시·서버 설정 시험 | NFR6, NFR8 |
| NFR6.7 | 의존성 버전은 잠금 파일(`package-lock.json`)로 고정하고, 병합 전 검증에서 `npm audit`의 알려진 취약점 보고(높음·치명)를 출력한다. 취약점이 있으면 보고만 하고 사람이 판단한다(개발 서버 전용 프로토타입). | 잠금 파일 존재, audit 출력 확인 | NFR6 |
| NFR8.1 | 프록시 대상 서비스 주소(u1, u2, u3)는 환경 변수로 바꿀 수 있고 기본값만 코드에 둔다. | 설정 검토 | NFR8 |

## 위협 고려

| 위협 | 대응 |
|---|---|
| 서버 응답 문자열로 스크립트 삽입(XSS) | NFR6.1: 텍스트로만 렌더링, Vue 기본 이스케이프 |
| 브라우저에서 결제 서비스 웹훅 직접 호출 | NFR6.3: 프록시가 연결하지 않음. 닿아도 서명 검증이 막는다(u3) |
| 다른 사람의 세션 ID 추측 | 세션 ID는 UUID 무작위 값. 서버가 세션별로 격리한다(u2). 추측 방지는 서비스 쪽 책임 |
| 세션 ID가 로그에 남음 | NFR6.4: 화면은 기록하지 않는다. 서버 로그는 앞 8자만 남긴다(u2, u3) |
| 오염된 의존성 | NFR6.7: 잠금 파일과 audit 보고 |
| 같은 머신 밖에서 개발 서버 접속 | NFR6.6: 루프백 바인딩 |

## Assumptions & Open Questions

- [assumption] 프록시는 개발 서버에서만 쓰이며 프로덕션 보안 헤더(CSP 등)는 적용하지 않는다. 근거: 프로덕션 빌드 배포가 없다(NFR8).
- [assumption] 세션 ID를 URL 쿼리로 보내는 구독은 개발 서버 로그에 남을 수 있다. 계약 C3가 이미 받아들인 가정이다.
- 열린 질문: 없음.
