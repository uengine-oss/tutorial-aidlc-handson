# u1-search-service 신뢰성 요구사항

## Sources

- [scope] Workflow-selected scope: classic
- [memory:M1] requirements.md(프로토타입), contract-summary.md(C4 읽기 전용이므로 재시도 안전), phases/construction.md(오류 처리: 조용한 실패 금지)

| ID | 요구사항 | 측정 방법 | 출처 |
|---|---|---|---|
| NFR2.1 | 서비스는 시작할 때 목업 데이터를 적재하고, 적재에 실패하면 기동을 거부한다(빨리 실패한다). 일부만 적재된 상태로 요청을 받지 않는다. | 잘못된 데이터 파일로 기동 시험에서 기동 실패 확인 | 오류 처리 규칙 |
| NFR2.2 | 처리하지 못한 예외는 500 `INTERNAL_ERROR`와 공통 오류 형식으로 돌려주고 서버 로그에 남긴다. 조용히 삼키지 않는다. | 강제 예외 시험 | 오류 처리 규칙 |
| NFR2.3 | 주차권 조회(C4)는 읽기 전용이어서 호출자가 같은 요청을 다시 보내도 같은 결과를 돌려준다(멱등). | 같은 요청 반복 시험 | contract-summary.md |
| NFR2.4 | 가용성 목표(SLA)는 정하지 않는다. 프로토타입이며 로컬에서만 동작한다. 서비스가 죽으면 실행 스크립트로 다시 띄운다. | 설계 확인 | classic 범위 |

## 장애 시 동작

| 장애 | 동작 |
|---|---|
| 목업 데이터 적재 실패 | 기동 거부 |
| 처리 중 예외 | 500 INTERNAL_ERROR, 로그 기록 |
| 서비스 중단 | 호출자(u4 화면, u2 예약 서비스)가 오류를 받는다. 이 서비스에는 복구 절차가 없다 |
