## 실패 상세

- 시험: u3 `PerformanceTest.aDuplicateWebhookIsAnsweredWithin20Milliseconds`
- 기대: 100회 최댓값 ≤ 20ms. 실제: 66.606ms.
- 당시 호스트 부하 평균 약 141~192(16코어). 부하가 높을 때 나오는 시간 시험 실패로 분류한다. 코드 결함인지는 부하가 낮은 상태의 재실행으로 가린다.
- 부하가 약 39~54로 내려간 뒤 재실행(11:01, 11:05): 이번에는 u3 서명 거부 20ms 시험(1차)과 중복 웹훅 20ms 시험(2차)이 번갈아 실패했다. 중복 웹훅은 중앙값 0.4~0.7ms, 최댓값 32~53ms(한도 20ms)였다. 서명 거부는 한 번 통과했을 때 중앙값 0.2ms, 최댓값 12.9ms. 즉 대부분의 요청은 한도보다 훨씬 빠르고 100회 중 드문 한 번이 20ms를 넘는다. 부하 때문인지(GC·스케줄링 지연) 코드 때문인지는 아직 가려지지 않았다.
- 같은 재실행에서 u2 `SseWireTest.aClientThatDisconnectsIsRemovedAfterTheNextWriteFails`(실제 소켓, 연결 끊김 정리)가 10초 제한을 넘겨 한 번 실패했고, 따로 다시 돌리면 통과했다(부하 약 54). 이 때문에 `-Pslow` 실제 180초 시험은 이번에도 실행되지 못했다.
- 조치: 목표·기준은 그대로 둔다(사람 결정: 부하 낮을 때 다시, 계속 재시도). 재실행 작업이 부하 40 미만을 기다리는 중이다. 이 글을 쓰는 시점의 부하 평균은 약 235~330이다.

## 실제 서비스 연동 확인

- u1~u3를 실제로 기동했고 `/actuator/health`는 모두 `UP`이다.
- u1에 빈 본문(`{}`)을 보내면 정확히 400(`INVALID_TEXT`)이다. u4 준비 확인이 기대하는 값이다.
- 추천: 200, 후보 3건(강남역 공영주차장 최적).
- 결제 요청: 202, 이어서 예약 조회가 약 1초 안에 `CONFIRMED`. 서버 기록상 결제 요청 00:57:59.912Z, 확정 00:58:00.011Z로 약 0.1초.
- 웹훅 직접 호출(서명 없음): 401. 내부 예약 경로 직접 호출: 404.
- 기동한 u1~u3는 모두 종료했고 남은 프로세스와 8081~8083 포트 점유가 없음을 확인했다.
- 화면(u4) 경유 확인: 다른 프로젝트의 서버가 `[::1]:5173`(IPv6)만 점유하고 있어 `run-local.sh`는 포트 검사에서 거부했다(IPv6만 점유돼도 거부함). u4는 127.0.0.1에 묶이므로 함께 뜰 수 있어, 이번 확인은 u1~u3와 u4(`npm run dev`)를 각각 띄워 진행했다. 따라서 `run-local.sh`의 한 번에 기동·정리 경로는 실제 서비스로 확인하지 못했다.
- 화면 경유(`http://127.0.0.1:5173`): 빈 본문 추천 요청 400, `smoke-local.sh` 5/5 통과(웹훅 경로 404, 내부 경로 404, 추천 200, 결제 202, 예약 `CONFIRMED`). 기록은 `.local-run/smoke.txt`.
- 서비스(u1~u4)는 브라우저 확인 뒤 종료했다. 우리 프로젝트의 PID 네 개만 종료했고, 다른 프로젝트의 `[::1]:5173` 서버는 그대로 두었다.

## 정리 중 있었던 실수와 안전한 방법

- 실수: 서비스를 끄려고 `lsof -i4TCP`와 `-a`를 겹쳐 쓴 명령을 만들었다. 이 형태는 지정한 포트가 아니라 머신의 IPv4 TCP 프로세스 전부(다른 프로젝트 서버, Docker 포함)를 골라 종료하게 된다. 사람이 실행 전에 거부해 실제로는 실행되지 않았다.
- 안전한 방법: 포트마다 `lsof -nP -iTCP:<포트> -sTCP:LISTEN`으로 PID를 찾고, `lsof -a -p <PID> -d cwd`로 작업 폴더가 `lab/aidlc-voice-parking-classic` 아래인지 확인한 PID만 종료한다. 이번 정리는 이 방법으로 했다.
- `run-local.sh`는 IPv6(`[::1]:5173`)만 점유돼도 포트 검사에서 거부한다.

## 실제 브라우저 증거에 대한 설명

브라우저에서만 확인되는 항목(EventSource 동작, 연결 6개 제한, 화면 수동 절차, 웹훅부터 화면까지 1초)은 Node/jsdom 통합 시험의 결과일 뿐 실제 브라우저에서 확인한 것이 아니다. 이 환경에는 실제 브라우저가 없어 Unverified로 두었다.
