# u3-payment-service 논리 구성 요소

## Sources

- [scope] Workflow-selected scope: classic

서비스 하나(프로세스 하나) 안의 논리 구성 요소를 적는다.

| 구성 요소 | 책임 | 적용되는 NFR 설계 |
|---|---|---|
| 웹 계층 | C2 결제 요청과 C6 웹훅 요청을 받아 입력을 검증하고 응답을 만든다. 웹훅 본문은 8KB 한정으로 원문 바이트를 읽는다. | 경계 입력 검증, 본문 한정 읽기(보안), 전역 예외 처리(신뢰성) |
| 요청 로그 필터 | 모든 요청의 경로·상태·시간을 기록한다. | 관측성 |
| 서명 검증기 | 원문 바이트의 HMAC-SHA256을 상수 시간으로 비교한다. 비밀 값을 시작할 때 읽고 없으면 기동을 거부한다. | 서명 검증, 비밀 값(보안) |
| Payment 서비스 | 결제 요청 처리, 웹훅 처리, 멱등과 직렬화. Payment·WebhookEvent·PgRequest 기록과 잠금(이벤트·키·Payment)을 소유한다. | 이벤트 단위 직렬화, 같은 키 원자 처리(신뢰성), 세분화된 잠금(확장성) |
| 예약 서비스 클라이언트 | u2 예약 생성(마감 1.5초, 재시도 없음)과 결과 반영(2초 제한, 간격 200ms, 최대 2회 재시도). | u2 호출 마감(성능, 신뢰성) |
| `PaymentGateway` 인터페이스 | `payment` 패키지에 있는, 결제를 모의 PG(또는 이후 실제 PG)에 요청하는 한 메서드와 요청 값 `PgPayment`. Payment 서비스가 아는 유일한 PG 접점이며 `pg`가 구현한다. | 패키지 경계(확장성) |
| 서명 계산 (`signature` 패키지) | HMAC-SHA256 계산(`HmacSigner`). 웹 계층의 서명 검증기와 모의 PG가 함께 쓴다. | 서명 검증(보안), 패키지 경계 |
| 웹훅 본문 필터 | 웹훅 경로 전용으로 본문을 8193바이트까지만 읽어 요청 속성에 담는다. | 본문 한정 읽기(보안) |
| 모의 PG (`pg` 패키지) | 시나리오·지연에 따라 결과를 정하고 지연 스케줄러에서 발송 실행기로 넘겨 웹훅 주소에 서명한 HTTP 호출을 한다. 걷어낼 수 있는 구성 요소다. | 스케줄러·발송 분리(성능), 시계·스케줄러 주입(신뢰성) |
| 시계 | 모든 시각과 모의 PG 지연의 유일한 출처. 시험에서 교체한다. | 시계 주입(신뢰성) |
| 상태 확인 | `/actuator/health` | 관측성 |

## 실패 영역과 영향 범위

- 서비스 전체가 하나의 실패 영역이다. 이 서비스가 죽으면 화면의 결제 요청과 승인·실패 웹훅 처리가 실패한다. 이미 만들어진 예약의 조회·구독·자동 취소(u2)에는 영향이 없다. 재시작하면 결제 기록과 예약된 알림이 사라진다.
- u2가 죽으면 결제 요청은 1.5초 안에 502로 실패하고 웹훅은 최대 약 6.4초 뒤 502로 실패한다. 추천(u1)에는 영향이 없다.
- 모의 PG의 자기 호출 실패는 그 결제 한 건의 승인 유실로 끝나며 다른 결제에 영향을 주지 않는다.
- 공유 자원은 없다. 데이터는 이 서비스의 프로세스 메모리에만 있고 다른 서비스와 공유하지 않는다. 비밀 값은 환경 변수로 이 서비스와 모의 PG(같은 프로세스)가 공유한다.
