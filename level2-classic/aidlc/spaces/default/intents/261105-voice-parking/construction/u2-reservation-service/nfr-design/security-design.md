| 비밀 값 없음 | 이 서비스는 비밀 값을 쓰지 않는다. 소스·설정에 키나 비밀번호 문자열을 두지 않고, 빌드 단계에 흔한 비밀 값 패턴 검색 시험을 넣는다. 웹훅 서명 검증은 u3 소관이다. | NFR6.1 |
| 경계 입력 검증 | 컨트롤러에서 세션 식별자(UUID), 예약 생성 본문(passId·idempotencyKey 비어 있지 않음과 100자 이하, durationHours 1~24), 결제 결과 본문(eventId 1~100자, outcome 허용값)을 검증한다. 검증은 서비스 로직보다 앞에서 하고, 어긋나면 엔드포인트별로 다음을 돌려준다: 조회·구독(`/api/reservations/**`)의 세션 식별자 오류는 401 MISSING_SESSION, 내부 경로(`/internal/**`)의 본문 오류(sessionId 형식 포함)는 400 INVALID_REQUEST. | NFR6.2 |

| 인증 없음 | 인증이 없다. 세션 ID는 식별용이며 인증을 우회하는 코드를 만들지 않는다. | NFR6.4 |
| 내부 경로 노출 차단 | (1) `/internal/**`는 화면의 Vite 프록시에 연결하지 않는다. (2) 서비스를 루프백 주소에만 연다(`server.address=127.0.0.1`, 환경 변수로 바꿀 수 있지만 기본값이 루프백이다). 같은 네트워크의 다른 기기에서는 포트 8082에 접속할 수 없다. (3) u3가 호출하는 u2 주소도 루프백 주소다. | NFR6.5 |
| 세션 ID 로그 최소화 | 요청 로그에는 세션 ID 앞 8자만 남기고 쿼리 문자열은 기록하지 않는다. 오류 본문에는 고정 문구와 오류 코드만 넣고 입력 원문을 되돌려 보내지 않는다. | NFR6.6 |

## 대안

- 내부 호출용 공유 토큰(환경 변수)을 `/internal/**`에 요구하는 안: 루프백 바인딩보다 방어가 한 겹 늘지만 u3와 u5-local-run이 함께 바뀌고 비밀 값이 하나 더 생긴다. 별도 배포 환경이 없고 모든 서비스가 한 머신에 있어 루프백 바인딩으로 충분하다고 보고 선택하지 않았다.

## 보안 헤더, 암호화

별도 보안 헤더와 암호화는 적용하지 않는다. 로컬 환경에서만 동작하고 민감 데이터(결제 정보)를 저장하지 않는다.

## 시험

- 설정 시험: 기본 설정의 `server.address`가 루프백인지 확인한다.
- 접속 시험: 기동한 서비스에 루프백 주소로는 접속되고, 이 머신의 비루프백 주소(있을 때)로는 접속이 거부되는지 확인한다. 비루프백 주소가 없는 환경에서는 이 시험을 건너뛰고 건너뛴 사실을 시험 결과에 남긴다.
- 두 세션으로 서로의 예약 ID를 조회·구독해 404가 오는지 시험한다.

## 다른 유닛에 넘기는 의무

- u3-payment-service: 이 서비스를 부르는 주소는 루프백 주소(`127.0.0.1`)로 둔다. `idempotencyKey`와 `passId`는 100자 이하로 보낸다(이 서비스는 초과하면 400 INVALID_REQUEST).
- u5-local-run: 이 서비스를 기본 설정(루프백 바인딩)으로 띄운다. `SERVER_ADDRESS`를 바꾸지 않는다.
- u4-web-ui: 구독 수 상한 초과 때의 503 `SUBSCRIPTION_LIMIT`을 일반 오류로 처리한다.

## Assumptions & Open Questions

- [assumption] `/internal/**`의 방어를 루프백 바인딩에 둔다. 같은 머신의 다른 프로세스는 서명 없이 결제 결과 반영을 호출할 수 있으며 이 잔여 위험은 받아들인다. 근거: 로컬 프로토타입이며 별도 배포 환경이 없다(NFR8). 공유 토큰이 필요하면 u3와 u5-local-run을 함께 바꾸는 변경으로 다룬다. 사람이 확인할 항목이다.
- [assumption] `passId`와 `idempotencyKey`의 길이 상한은 100자다. 계약 C5에는 없는 제약이다. 근거: 요구사항이 길이를 정하지 않았고 목업 ID는 짧다.
