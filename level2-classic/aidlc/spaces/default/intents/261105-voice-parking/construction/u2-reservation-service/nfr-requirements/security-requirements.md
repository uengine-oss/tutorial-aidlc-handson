| ID | 요구사항 | 측정 방법 | 출처 |
|---|---|---|---|
| NFR6.1 | 이 서비스는 웹훅 서명 비밀 값을 포함한 어떤 비밀 값도 가지지 않는다. 소스 코드와 설정에 비밀 값이 하나도 들어 있으면 안 된다. (웹훅 서명 검증은 u3-payment-service가 맡는다.) | 소스와 설정 파일에서 비밀 값 패턴 검색 결과 0건 | NFR6, 보안 규칙 |
| NFR6.2 | 모든 입력은 시스템 경계에서 검증한다. `X-Session-Id`와 쿼리 `sessionId`는 UUID 형식, 예약 생성의 `passId`와 `idempotencyKey`는 비어 있지 않은 문자열, `durationHours`는 1~24의 정수, 결제 결과의 `eventId`는 1~100자, `outcome`은 APPROVED 또는 FAILED여야 한다. 어긋나면 BR3.1은 401, 그 밖의 형식 오류는 400을 돌려주고 아무것도 바꾸지 않는다. | 잘못된 입력별 단위 시험 | NFR6, BR1.1, BR2.1, BR3.1 |
| NFR6.3 | 세션은 자기 예약만 조회·구독할 수 있다. 다른 세션의 예약 ID로 요청하면 존재 여부를 알려 주지 않고 404 NOT_FOUND를 돌려준다. | 두 세션으로 교차 조회·구독 시험 | NFR6, BR3.2, FR8.1 |
| NFR6.4 | 인증은 없다. 세션 ID는 식별용 익명 UUID이며 비밀 값이 아니다. 인증이나 인가를 우회하는 코드는 만들지 않는다. | 설계 확인 | NFR6, Q4 |
| NFR6.5 | 내부 경로 `/internal/**`(예약 생성, 결제 결과 반영)는 화면 쪽에 노출하지 않는다. Vite 프록시는 `/api/reservations`만 이 서비스로 보내며 `/internal`은 연결하지 않는다. 서비스 간 호출은 로컬 주소로만 한다. | 프록시 설정 검토 (u5-local-run, u4-web-ui 연동 시) | NFR6, NFR8 |
| NFR6.6 | 구독 URL의 `sessionId` 쿼리 파라미터는 서버 로그에 남을 수 있으므로 요청 로그에는 세션 ID 앞 8자만 남기고 전체 값을 기록하지 않는다. 오류 응답에 입력 원문을 되돌려 보내지 않는다. | 로그 출력 시험, 오류 응답 시험 | NFR6, contract-summary.md(C3 가정) |
| NFR8.1 | 다른 서비스 호출 주소(u1-search-service)는 환경 변수로 주입하며 코드에 하드코딩하지 않는다. | 설정 검토 | NFR8 |

## 위협 고려

| 위협 | 대응 |
|---|---|
| 다른 사람의 예약 ID로 조회·구독 | NFR6.3 (세션 불일치는 404) |
| 같은 세션의 반복 결제 요청으로 대기 예약 누적 | BR1.3 (세션당 결제 대기 1건), 요청 빈도 제한은 하지 않음 (로컬 프로토타입) |
| 위조된 결제 결과로 예약 확정 | 이 서비스는 서명을 보지 않는다. `/internal` 경로는 프록시에 연결하지 않고 서명 검증은 u3가 한다. 서명 검증이 없는 호출자는 이 서비스에 닿지 않는다는 가정 아래에 있다 |
| 구독 연결을 많이 열어 자원 고갈 | 요청 빈도·연결 수 제한은 하지 않는다 (로컬 프로토타입, 데모 규모) |
| 세션 ID가 URL에 실려 로그에 남음 | NFR6.6 |

## Assumptions & Open Questions

- [assumption] `/internal/**` 경로를 로컬 네트워크에서 직접 호출하는 것을 막는 인증은 두지 않는다. 근거: 별도 배포 환경이 없고(NFR8) 모든 서비스가 한 머신의 로컬 주소에서 동작한다. 호출자가 u3로 한정된다는 것은 환경 가정이다.
- 열린 질문: 없음.
