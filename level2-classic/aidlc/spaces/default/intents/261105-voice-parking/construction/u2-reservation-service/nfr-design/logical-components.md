# u2-reservation-service 논리 구성 요소

## Sources

- [scope] Workflow-selected scope: classic
- [memory:M1] unit-of-work.md(U2), components.md(Reservation, Notification), nfr-design의 성능·보안·확장성·신뢰성·관측성 설계

서비스 하나(프로세스 하나) 안의 논리 구성 요소를 적는다.

| 구성 요소 | 책임 | 적용되는 NFR 설계 |
|---|---|---|
| 웹 계층 | C3(조회·구독)와 C5(예약 생성·결과 반영) 요청을 받아 입력을 검증하고 응답을 만든다. 구독 엔드포인트에서 소유 확인과 대체 스냅샷 생성을 한다. | 경계 입력 검증, 세션 격리(보안), 전역 예외 처리(신뢰성) |
| 요청 로그 필터 | 모든 요청의 경로·상태·시간을 기록한다. | 관측성 |
| Reservation | 예약 생성, 결제 결과 반영, 자동 취소, 조회. 예약 저장소와 판정 기록을 소유한다. | 예약 단위·세션 단위 잠금(신뢰성, 확장성), 시계 기반 마감, 짧은 임계 구역(성능) |
| 마감 타이머 | 예약마다 마감 시각에 한 번 울려 Reservation의 취소를 호출한다. 취소 스케줄러(스레드 2개)에서 실행한다. | 시계 주입, 푸시와 분리(신뢰성, 성능) |
| Notification | 구독 목록과 예약별 최신 스냅샷을 소유한다. `publish`는 version 규칙으로 최신 스냅샷을 갱신하고 구독 연결별 쓰기 큐에 넣기만 한다(입출력 없음). Reservation을 참조하지 않는다. | 패키지 경계(확장성), 연결별 순서(성능), 푸시 실패 격리(신뢰성) |
| 연결별 쓰기 큐 | 연결마다 FIFO 큐(상한 16)와 배출 중 표시. 한 연결에 배출 작업은 하나뿐이다. 스냅샷과 연결 유지 신호가 같은 큐를 쓴다. | 순서·직렬 쓰기(성능, 신뢰성) |
| 푸시 실행기 | 연결 배출 작업을 실행한다(스레드 상한 32, 큐 없는 직접 인계, 구독 수 상한 32). | 푸시 실행기(성능, 확장성) |
| 감시 스케줄러 | 연결 유지 신호를 15초마다 큐에 넣고, 1초 넘게 끝나지 않은 쓰기의 연결을 닫는다(스레드 1개). | 푸시 실패 격리(신뢰성) |
| 검색 서비스 클라이언트 | u1 주차권 조회. 전체 마감 1.5초, 시도 제한 500ms, 간격 200ms. | u1 호출 마감(성능, 신뢰성) |
| 시계 | 모든 시각과 마감 판정의 유일한 출처. 시험에서 교체한다. | 시계 주입(신뢰성) |
| 상태 확인 | `/actuator/health` | 관측성 |

## 실패 영역과 영향 범위

- 서비스 전체가 하나의 실패 영역이다. 이 서비스가 죽으면 화면의 예약 조회와 실시간 알림, u3의 예약 생성과 결과 반영이 실패한다. 추천(u1)에는 영향이 없다. 재시작하면 예약이 모두 사라진다.
- u1이 죽으면 이 서비스의 예약 생성만 실패(502)하고 이미 만들어진 예약의 결과 반영·취소·조회·구독은 그대로 동작한다.
- 한 구독 연결의 장애는 그 연결에만 영향을 준다. 한 예약의 잠금은 다른 예약에 영향을 주지 않는다.
- 공유 자원은 없다. 데이터는 이 서비스의 프로세스 메모리에만 있고 다른 서비스와 공유하지 않는다.
