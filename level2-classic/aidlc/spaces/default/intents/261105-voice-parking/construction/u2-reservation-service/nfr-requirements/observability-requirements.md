# u2-reservation-service 관측성 요구사항

## Sources

- [scope] Workflow-selected scope: classic
- [memory:M1] requirements.md(NFR1, NFR5), rules.md의 BR2.2, BR4.4, BR4.6, phases/operation.md(새 서비스마다 상태 지표와 오류율 지표 최소 하나), team.md(별도 배포 환경 없음), security-requirements.md의 NFR6.6

| ID | 요구사항 | 측정 방법 | 출처 |
|---|---|---|---|
| NFR1.5 | 서비스는 상태 확인 경로(`GET /actuator/health`)를 제공하고 기동되면 UP을 돌려준다. | 단위/통합 시험 | 운영 규칙(상태 지표) |
| NFR1.6 | 요청마다 로그 한 줄에 경로, 상태 코드, 처리 시간(ms), 세션 ID 앞 8자를 남긴다. 전체 세션 ID와 쿼리 문자열은 로그에 남기지 않는다. | 로그 출력 시험 | NFR1, NFR6.6 |
| NFR1.7 | 오류 응답(4xx, 5xx)은 오류 코드와 함께 로그에 남는다. 오류율은 로그에서 셀 수 있다. | 로그 출력 시험 | 운영 규칙(오류율 지표) |
| NFR5.9 | 예약 상태가 바뀔 때마다 로그 한 줄에 예약 ID, 이전 상태, 새 상태, version, 원인(승인, 실패, 자동 취소, 마감 이후 결과)을 남긴다. | 상태 전이별 로그 출력 시험 | NFR5, NFR2, BR2.1, BR2.4 |
| NFR5.10 | 결제 결과 반영의 거부와 중복(BR2.2)은 예약 ID, eventId, outcome, 현재 상태와 함께 로그에 남긴다. | 로그 출력 시험 | NFR5, FR5.4 |
| NFR1.8 | 푸시 로그: 구독 시작·종료, 푸시 실패(BR4.4)를 예약 ID와 함께 로그에 남기고, 결과 반영 요청 수신부터 연결에 쓰기까지의 시간(ms)을 푸시 로그에 포함한다. 시험에서 NFR1.1을 확인하는 데 이 값을 쓴다. | 로그 출력 시험 | NFR1, BR4.6 |

## 범위 밖

- 외부 모니터링 시스템, 분산 추적, 대시보드, 알림은 이번 프로토타입에서 두지 않는다 (별도 배포 환경 없음). SLO 수치는 정하지 않으며 위 요구사항이 로컬에서 확인 가능한 최소 관측성이다.
