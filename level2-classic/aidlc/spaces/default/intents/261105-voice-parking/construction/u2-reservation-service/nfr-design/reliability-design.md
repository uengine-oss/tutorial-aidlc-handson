| 설계 | 방식 | 충족하는 요구사항 |
|---|---|---|
| 판정 기록으로 멱등 | 결과 반영은 예약 단위 잠금 안에서 (예약 ID, eventId) 판정 기록을 먼저 찾고, 있으면 처음 판정을 그대로 돌려준다. 없을 때만 상태를 판정하고 기록을 남긴다. 상태 변경과 기록 저장은 같은 잠금 안에서 일어난다. | NFR5.1 |
| 직렬화 | 잠금 획득 순서는 세션 잠금 → 예약 잠금 → Notification → 연결 큐이며 역순은 없다. 예약 단위 잠금이 결과 반영·자동 취소·마감 확인을 직렬화한다. 세션 단위 잠금이 예약 생성의 멱등 키 조회와 결제 대기 확인과 저장을 직렬화한다. 순서는 BR1.2(멱등 키)를 먼저, 그다음 BR1.3(결제 대기)이다. 같은 키 동시 요청 중 뒤의 요청은 200으로 같은 예약을 받는다. | NFR5.2 |
| 거부와 중복 기록 | 상태 때문에 거부된 결과(BR2.2)는 예약 ID, eventId, outcome, 현재 상태와 함께 로그 한 줄로 남긴다. 중복 eventId 재응답도 같은 필드로 로그 한 줄을 남긴다(기능 설계 BR2.1이 로그를 요구하지 않지만 금지하지도 않는다). | NFR5.3 |
| 시계 기반 마감 | 마감 판정은 `now >= paymentRequestedAt + 180초`로 시계에서 한다. 타이머가 늦게 울려도 결과 반영 경로가 먼저 취소로 확정한다. | NFR2.3 |
| 시계 주입 | 모든 시각은 `Clock` 인터페이스에서 읽고 타이머도 같은 시계를 기준으로 예약한다. 시험은 시계를 앞으로 돌려 경계를 검증한다. | NFR2.4 |
| 푸시 실패 격리 | 상태 변경이 끝난 뒤 연결별 쓰기 큐와 푸시 실행기에서 쓴다(performance-design.md). 쓰기 예외는 그 구독만 제거하고 로그에 남기며 상태나 다른 구독에 영향을 주지 않는다. 쓰기 하나의 상한 시간은 1초이며 감시 스케줄러가 넘긴 연결을 끊는다. 연결 큐가 16을 넘어도 그 연결을 끊는다. | NFR5.4 |
| 타이머 해제 | 예약이 결제 대기를 벗어나면(결과 반영, 마감 이후 취소) 예약 단위 잠금 안에서 타이머 핸들을 취소한다. 이미 울리기 시작한 타이머는 잠금을 기다리다가 상태가 결제 대기가 아님을 보고 아무것도 하지 않는다(BR2.4). 타이머 콜백은 설정 가능한 마감(`reservation.payment-timeout`)을 기준으로 직접 호출해 시험할 수 있다. | NFR2.1, NFR2.4 |
| 스케줄러와 시계 | 스케줄러는 주입한 `Clock`을 쓴다(`ThreadPoolTaskScheduler`의 시계 설정). 시험은 (a) 시계를 돌려 경계 판정을 검증하고 (b) 타이머 콜백을 직접 호출하고 (c) 마감을 2초로 줄여 실제 스케줄러 경로를 한 번 검증한다. | NFR2.4 |
| 구독 연결 설정 | `SseEmitter` 시간 초과는 10분으로 둔다(180초 대기보다 길게). 연결 유지 신호는 15초마다 연결 큐에 넣는다. 시간 초과·오류·완료 콜백에서 구독을 제거한다. | NFR5.4 |
| u1 호출 | 시도 제한 350ms, 시도 간격 200ms, 전체 마감 1.5초, 최대 3회 호출(performance-design.md). 읽기 전용이라 재시도해도 안전하다. 마감 안에 성공하지 못하면 502 UPSTREAM_FAILED를 돌려주고 예약은 만들지 않는다. 호출자가 먼저 포기해도 같은 멱등 키로 다시 요청하면 이어 갈 수 있다. | NFR5.5 |
| 전역 예외 처리 | 처리하지 못한 예외는 500 INTERNAL_ERROR와 공통 오류 형식으로 돌려주고 로그에 남긴다. 상태 변경은 잠금 안에서 한 번에 저장하는 값 교체로 하고, 중간에 예외가 나면 이전 값이 남는다. | NFR5.6 |
| 재시작 | 재시작하면 모든 메모리 상태가 사라진다. 시작할 때 예약은 비어 있고 타이머를 복구하지 않는다. 사라진 예약에 대한 요청은 404 NOT_FOUND다. | NFR5.7 |
| 가용성 목표 없음 | 가용성 목표는 정하지 않는다. 서비스가 죽으면 실행 스크립트로 다시 띄운다. 회로 차단기는 두지 않는다(호출처가 u1 하나이고 마감이 짧다). | NFR5.8 |
| 품질 게이트 | 병합 전에 `mvn verify`(시험과 JaCoCo 80% 검사 포함)를 실행하는 것을 병합 전 검증으로 본다. 이 실행은 u5-local-run의 검증 스크립트로 제공한다. | NFR7.1 |

## 장애 시 동작

| 장애 | 동작 |
|---|---|
| u1 중단·지연 | 예약 생성이 마감 1.5초 안에 502. 예약 없음. 같은 키로 다시 요청 가능 |
| 푸시 쓰기 실패·지연 | 그 구독만 제거. 화면은 재연결해 최신 스냅샷을 다시 받는다 |
| 타이머 지연 | 도착하는 결과가 시계로 마감을 판정한다 |
| 재시작 | 예약 소실. 처음부터 다시 진행 |

## Assumptions & Open Questions

- [assumption] 푸시 쓰기 하나의 상한은 1초, 연결 큐 상한은 16, SseEmitter 시간 초과는 10분이다. 근거: 1초 예산(NFR1)을 넘는 쓰기는 의미가 없고, 느린 클라이언트가 연결 하나 밖의 처리에 영향을 주지 않게 하는 값이다.
- 열린 질문: 없음.
