# Domain Design 질문

## Q1. [아키텍처] 코드 구성 요소(컴포넌트)를 어떤 단위로 나눌까요?
서비스(배포 단위)를 몇 개로 묶을지는 다음 단계(Units Generation)에서 정합니다. 여기서는 책임과 데이터 소유가 다른 논리적 덩어리만 정합니다.

A. 5개로 세분화 (제안)
   - QueryParser: 음성 텍스트에서 장소·시간 추출
   - Recommendation: 후보 조회와 종합 점수 계산 (주차장·주차권 데이터 소유)
   - Reservation: 예약 상태와 180초 자동 취소 (예약 소유)
   - Payment: 모의 PG 결제 요청과 승인·실패 웹훅 처리 (결제 소유)
   - Notification: SSE 푸시 (화면 구독 관리)
   장점: 변경 이유가 서로 달라 독립적으로 테스트하기 쉽고, 결제·예약·알림이 각각 마이크로서비스 후보가 된다. 단점: 컴포넌트 간 호출이 늘어난다.
B. 3개로 통합
   - Search: 입력 해석 + 후보 조회 + 점수 계산
   - Booking: 예약 + 결제 + 자동 취소
   - Notification: SSE 푸시
   장점: 호출이 적고 단순하다. 단점: 결제 웹훅 처리와 예약 타이머가 한 덩어리가 되어 경계 동시성(180초) 테스트가 복잡해진다.
X. Other (please specify)

[Answer]: A
